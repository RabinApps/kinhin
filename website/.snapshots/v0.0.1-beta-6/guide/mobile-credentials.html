GUIDE / MOBILE RELEASES

Mobile release credentials

View .mdEdit on GitHub

Every secret the release workflow reads, where to get it, and what each one is for. None of them are stored by kinhin. Store them as repository secrets (Settings, then Secrets and variables, then Actions). The workflow maps them into the lanes, and each lane checks for the ones it needs before any store call.

App Store Connect API key#

The key lets fastlane upload builds without your Apple ID password.

  1. In App Store Connect, open Users and Access, then Integrations, then App Store Connect API.
  2. If the API has not been enabled for the team, the Account Holder must request access there first.
  3. Choose Generate API Key (a Team key). Only the Account Holder or an Admin can create a team key, and each key is assigned a role. Apple's API page does not list which roles can upload builds, so confirm the key works with one upload before you rely on it. Team keys apply to every app in the team. Individual keys belong to one user.
  4. Download the .p8 file. Apple's page says API keys "can only be downloaded once": if you lose it, revoke the key and create another.
  5. Copy the Key ID into ASC_KEY_ID, and the Issuer ID shown at the top of the page into ASC_ISSUER_ID.
  6. Store the contents of the .p8 file as ASC_KEY_P8. The workflow writes it to a temporary file during the job and deletes it afterwards. On macOS, pbcopy < AuthKey_XXXX.p8 copies it.

Revoke a key you no longer use. Anyone with the .p8 and the IDs can act with its role.

Match: certificates and profiles#

match keeps signing certificates and provisioning profiles in a git repository, encrypted with MATCH_PASSWORD.

  1. Create an empty private repository for it, for example my-org/certificates.
  2. Set MATCH_GIT_URL to its SSH or HTTPS URL. kinhin's Matchfile reads this variable; match itself takes the URL as git_url. The CI runner needs read access to the repository. match can authenticate with its git_private_key, git_basic_authorization or git_bearer_authorization options, which the templates do not set yet.
  3. Choose MATCH_PASSWORD, and keep a copy somewhere safe. Without it the repository cannot be decrypted.
  4. Create the certificates once from your own Mac: MATCH_READONLY=false bundle exec fastlane match appstore. After that the CI job runs match readonly and only reads them.

Apple team and bundle ID#

  • APPLE_TEAM_ID is the 10-character team ID. It is in the Membership details section of your Apple Developer account page (developer.apple.com/account). Apple's help index does not document this location, so check it against your own account.
  • APP_IDENTIFIER is the bundle ID, which must match the app in App Store Connect. Create the app there first, with the same bundle ID.

Google Play service account#

Play uploads use a service account that the Play Developer API trusts.

  1. In Google Cloud, create a project, or use an existing one, and enable the Google Play Android Developer API.
  2. Create a service account, and create a JSON key for it. Keep the file private.
  3. In Play Console, open Users and permissions, invite the service account's email address, and grant it release permissions for your app. Google lists Release apps to testing tracks as the permission for testing-track releases. Its permissions page does not say which permission a service account needs, so confirm the upload works on your first try. Uploading to a testing track needs the permission above. The first upload of a new app is covered below.
  4. Store the whole JSON file as PLAY_SERVICE_ACCOUNT_JSON.

The first upload of a new app is made by hand in Play Console, as the fastlane supply docs say. Once the app exists and has a release, the lanes can upload.

Android upload keystore#

Google Play App Signing holds the app's signing key. You sign uploads with an upload key, which is the keystore below.

keytool -genkeypair -v -keystore upload.keystore -alias upload -keyalg RSA -keysize 2048 -validity 10000
  • ANDROID_KEY_ALIAS is the alias you chose (upload above).
  • ANDROID_KEYSTORE_PASSWORD and ANDROID_KEY_PASSWORD are the passwords you entered.
  • ANDROID_KEYSTORE_BASE64 is the keystore, base64-encoded: base64 -i upload.keystore | pbcopy on macOS.

Back up the keystore and its passwords. If you lose the upload key, Google says you are not locked out. Request a reset in Play Console, in the Upload key certificate section, after exporting the new key's certificate in PEM format.

.NET MAUI signing#

The iOS lane runs dotnet publish after match, so the certificate and profile must be in the keychain first. Use the identity and profile that match installed. Set them as repository variables (not secrets; they are not sensitive):

VariableValue
MAUI_CODESIGN_KEYThe signing identity, for example Apple Distribution: Your Name (ABCDE12345)
MAUI_PROVISIONING_PROFILEThe provisioning profile name that match installed, for example match AppStore com.example.app

The Android lane signs the AAB with the same upload keystore as the Gradle projects (ANDROID_KEYSTORE_BASE64 and the other Android secrets above). Nothing else changes for MAUI.

Checking a secret before a run#

A lane names the missing variables and stops before any store call. For example, fastlane ios beta without ASC_KEY_ID fails with Missing environment variables: ASC_KEY_ID, .... A variable can be set but still wrong. Those show up later, as an authentication or signing error, which the troubleshooting page covers.

Sources#

Checked against these pages. Where a page does not settle a point, the guide says so.

  • Apple, App Store Connect API: https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api/ (who requests access, which roles create team and individual keys, and that a private key can be downloaded only once).
  • fastlane, match: https://docs.fastlane.tools/actions/match/ (MATCH_PASSWORD, readonly, the CI recommendation, and match appstore).
  • fastlane, setup_ci: https://docs.fastlane.tools/actions/setup_ci/ (the temporary keychain and readonly on CI; iOS and macOS).
  • fastlane, supply: https://docs.fastlane.tools/actions/supply/ (json_key_data, and that a new app's first build is uploaded manually).
  • Google, Play Developer API: https://developers.google.com/android-publisher/getting_started (service account, enabling the API, and inviting the service account in Play Console).
  • Google, Play Console permissions: https://support.google.com/googleplay/android-developer/answer/9844686 (the Release apps to testing tracks permission).
  • Google, Play App Signing upload key reset: https://support.google.com/googleplay/android-developer/answer/9842756.
  • fastlane 2.241.0 gem metadata: required_ruby_version >= 3.2.0, read with gem spec fastlane -v 2.241.0.

Not settled by these pages: the Apple role that can upload builds, the Team ID location (Apple's help index does not list it), and the Play permission a service account needs for test-track uploads. Check each one in the console before you rely on it.
