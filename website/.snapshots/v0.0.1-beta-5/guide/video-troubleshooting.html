Troubleshooting videos

View .mdEdit on GitHub

The messages a video build is most likely to print, and what to do. Find the text your build printed in the left column.

← Back to Add videos to your project · Config reference · Recordings

The build prints the pipeline's own output as it runs. Read the whole log, not only the last line: the line above the failure usually says why. kinhin doctor checks your container runtimes.

You seeWhat to do
videos build in a container, and neither Apple's container nor Docker is runningStart one: container system start (install with brew install container), or open Docker Desktop. --runtime container or --runtime docker forces one and says why it is not usable.
kinhin video validate lists problems and exits 3Each line names the scene or setting and what is wrong. Nothing was rendered, so fix the file and run kinhin video validate again.
this video image predates 'kinhin video validate'The image for your kinhin version is older than the check. Update kinhin, or pass --image with a newer image.
no .kinhin/videos/ in <path> or no video "x"You are in the wrong directory, or the file is missing. kinhin video list shows what is found. kinhin video init x creates it. --dir PATH points at another repository.
could not get the video image ghcr.io/...Check the network. The image for your kinhin version must be published: a development build of kinhin has no published image, so pass --image or set KINHIN_VIDEO_IMAGE. If the package is private, sign in with docker login ghcr.io.
The build stops with a message from the pipelineThe log above the final line says why: a scene with no id, an unknown theme (the message lists the ones that exist), a clip that is not in the adapter, or a claim that claims.json forbids. Fix the config and run the build again. Scenes you did not change come from the render cache, so the rerun is fast.
no space left or read-only file systemThe image is about 1 GB and a build needs a few GB free. Free disk space. Apple's container keeps its images and builder cache under your home folder; docker system prune frees Docker's.
scene "x": no clip "app" in the acme adapterThe adapter does not declare that clip, or its file is missing. Add the clip to .kinhin/videos/adapters/<name>/adapter.yml and put the recording at reference/<clip>.mp4 (a terminal clip may also have -dark, -portrait and -dark-portrait variants). See Recordings.
theme "x": ... is missing or ... must be a colourA theme file in .kinhin/videos/themes/ is incomplete. Add extends: midnight (or another theme) and write only what you change. Colours are #rrggbb. The message names every problem at once. See Your own theme.
"Windows" is planned, not shipped (a claims failure)A scene mentions something your claims.json lists as planned without saying so, or it uses a forbidden word. Reword the line, or say that it is planned. See Keep it honest.
A music file or font is not foundPaths are relative to your repository, and the repository is mounted read-only in the container. Check that the file is committed and inside the repository, and that its extension is mp3, m4a, wav, flac or ogg. Fonts go in .kinhin/videos/fonts/.
music search says the library is rate limitingAnonymous use allows about 20 searches a minute and 200 a day. Wait, or set KINHIN_OPENVERSE_CLIENT_ID and KINHIN_OPENVERSE_CLIENT_SECRET from a free Openverse application. Tracks built into the image still show up offline.
add refuses a track: is licensed ..., which kinhin does not put in a videoOnly CC0 and public-domain tracks are accepted, and CC BY with --license cc-by. Non-commercial, no-derivatives and share-alike tracks are never added. Pick another result.
add says which video? or there is no videoName the video with --video <name> when the folder has several, or run kinhin video init first. --no-config only downloads the track.
did not download the trackThe file is over 50 MB, is not mp3, m4a, wav, flac or ogg, is not served over https, or its source link is gone. Try another result. preview shows the source page.
--on-fleet: kinhin-video.yml is not on <branch>Run kinhin video init --workflow, commit and push the file, then try again. --on-fleet also needs gh signed in (gh auth login) and a runner with Docker that matches --runs-on.

| A rebuild shows an old picture or voice | Framed recordings, drawn scenes and the voice of each sentence are reused while nothing that shapes them has changed. If one is stale, delete .kinhin/videos/.cache/ (or just its frames/, scenes/ or voice-cache/ folder) and build again. With video/scripts/build.sh, RENDER_FORCE=1 (pictures) and VOICE_FORCE=1 (voice) do the same for one build. | | no scene "x" in this video (its scenes: ...) | --scene takes scene ids from the video's file, comma-separated. The message lists them. |

Builds feel slow? Every build prints how long each step took. Try --scene and --watch while iterating (see Faster rebuilds). kinhin bench video times the image pull, a clean build and a cached rebuild on this Mac; see Benchmarks.

Still stuck? Open an issue with the full build log, with any token or key removed.
