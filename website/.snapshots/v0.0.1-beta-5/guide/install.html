Installing and updating kinhin

View .mdEdit on GitHub

The install script in detail, and update checks.

← Back to README

Install script#

Latest release:

curl -fsSL https://github.com/RabinApps/kinhin/releases/latest/download/install.sh | bash

Pinned version, or from a local DMG (air-gapped machines):

curl -fsSL .../install.sh | bash -s -- v0.1.0
bash scripts/install.sh /path/to/kinhin-0.1.0-arm64.dmg

The script sha256-verifies the DMG against the release checksums.txt, copies kinhin.app to /Applications, and symlinks the kinhin CLI into your bin dir — the first writable of /opt/homebrew/bin, /usr/local/bin, and ~/.local/bin. Release artifacts are Developer ID signed and notarized, so the app launches with no Gatekeeper prompts — the Open-Anyway dance only applies to old releases or locally built copies (clear it with xattr -cr /Applications/kinhin.app). Remove everything with bash scripts/install.sh --uninstall (config and your Keychain PAT are kept).

Installing Tart#

Tart runs the macOS runner VMs (and optional Linux VMs). The app's setup window installs it for you; from the terminal the same installer is one command:

kinhin setup repair tart      # skipped if tart is already on your PATH

kinhin doctor shows the tart state. When it reports tart: NOT FOUND or tart: INSTALLED BUT KILLED ON LAUNCH, it prints the exact repair commands for that state, and the app's setup checklist offers them as one-click fixes. Use those rather than typing brew commands from memory; this section is the only place the manual commands are documented.

These are the manual equivalents, for machines where kinhin is not installed yet or Homebrew must be driven by hand:

# Install (what `kinhin setup repair tart` runs)
brew tap openai/tools
brew trust openai/tools
brew install openai/tools/tart

# If `kinhin doctor` reports "INSTALLED BUT KILLED ON LAUNCH": the OpenAI-tap bottle is un-notarized
# (openai/homebrew-tools#27) and Gatekeeper kills it. Roll back to a notarized build:
brew uninstall openai/tools/tart openai/tools/softnet
brew tap openai/cli
brew trust openai/cli
brew install openai/cli/tart

Re-run kinhin doctor afterwards; it offers to move back to the OpenAI tap once a fixed bottle ships. The commands doctor prints are authoritative if they differ from this page.

Installing a Linux runtime#

Linux jobs are optional. Tart Linux VMs need nothing beyond Tart. For containers, use apple/container first; choose Docker only if you already run a Docker provider. The runtime comparison explains the trade-offs.

apple/container (recommended)#

kinhin setup repair container      # installs the container CLI and starts its service

These are the manual equivalents:

brew install container
container system start --enable-kernel-install

--enable-kernel-install installs the default Linux kernel. Without it, container system start stops to ask a question, and every container run then fails with "default kernel not configured". Then bake the image with kinhin image prepare --container.

Docker#

kinhin setup repair docker installs Docker Desktop by default. Pick another provider with --method orbstack or --method colima.

brew install --cask docker-desktop     # --method desktop (Docker Desktop: open it once after installing)
brew install --cask orbstack           # --method orbstack (OrbStack: open it once after installing)
brew install colima docker && colima start   # --method colima (command line only, no app)

Docker Desktop needs macOS 15 or newer and at least 4 GB of RAM. Then bake the image with kinhin image prepare --docker. kinhin does not configure or start your Docker provider; it only runs containers in it.

Both are also what kinhin video build uses to build videos of your own product; the first build pulls a video image of about a gigabyte.

How updates and installs are verified#

  • Install script: it refuses a download without checksums.txt, fetches over https only, and never strips the quarantine attribute. The copy attached to a release is stamped with the Developer ID Team ID of the shipped app, so it refuses an app that is not signed by that team or not accepted by Gatekeeper. A copy run from a checkout or a fork has no Team ID and can only verify that the signature is valid. A local DMG is checked against DMG.sha256 when one sits next to it.
  • In-app update: the menu bar app uses Sparkle. Each update archive must carry an EdDSA signature made with the release key whose public half is SUPublicEDKey in the installed app. Sparkle refuses an archive that fails that check, and it installs only over the running app with the same code signature. A Developer ID build also needs its own Gatekeeper-accepted, notarized signature.

Full uninstall#

kinhin cleanup --all               # VMs, images, caches
kinhin daemon uninstall            # the LaunchAgent
bash scripts/install.sh --uninstall   # the app and the CLI

--uninstall keeps your config and the Keychain PAT. To remove those too, delete the kinhin config directory and the kinhin entries in Keychain Access.

Update checks#

After installing, the menu bar app checks for a new release at most once a day (Sparkle's scheduled check, SUScheduledCheckInterval in Info.plist). When one is found, the status-bar menu shows Update available — kinhin x.y.z…, and Settings → App offers Install Update…. Sparkle then downloads, verifies and installs the update over the running app and relaunches it, so there is no DMG to drag around. Any build, including a release build, honors KINHIN_UPDATE_FEED=https://…/appcast.xml to point the updater at another appcast. The feed only supplies candidates: each archive must still be signed with the build's SUPublicEDKey, so a redirected feed cannot install unsigned code.

The daemon survives an upgrade too. The app's LaunchAgent points at the app's own binary, so after an update the launch-time check finds a daemon still running the previous build and restarts it (launchctl kickstart). Running jobs are interrupted by that restart.
