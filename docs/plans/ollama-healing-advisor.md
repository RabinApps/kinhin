# Plan: healing agent on Ollama, with a fast System 1 model and a custom LLM

## Context

The healing agent (`docs/healing.md`) fixes known fleet problems with rules. For problems no rule covers, it asks an
advisor to pick one fix from an allowlist. The only advisor today is Apple Intelligence (Foundation Models), which needs
macOS 26 with Apple Intelligence on. Anyone else gets rules only.

The goal: let the agent use Ollama, with the user choosing the models. A fast decision model (System 1) answers first.
When it is unsure or picks nothing, a larger custom model (the LLM, any model pulled or built with `ollama create`)
answers. Easy problems stay cheap; hard ones get the bigger model.

Decisions taken from the user's answers:
- **Cascade:** System 1 answers first. If its pick is not confident, or it says none, the LLM is asked.
- **System 1 is an Ollama decision model** (`clef-flash` or `nimble`), not Apple Intelligence. `ai: auto` keeps its current meaning (Apple
  Intelligence, else rules only) and is not part of the cascade.
- **Host:** any URL is accepted, so redacted problem and log text can leave this Mac. That changes the privacy stance in
  `docs/security.md` and `docs/healing.md`, which say the advisor makes no network call today. Guard I added, not in the
  answers: a non-loopback host must use `https`.

## Current state

  `advise(_:)`. `HealingAdvice` carries `remediation`, `confident`, `explanation`. `NoHealingAdvisor` and
  `StubHealingAdvisor` implement it.
- `FoundationModelsHealingAdvisor` holds the prompt, instructions, and the 20 s deadline. The prompt code is plain Swift,

- `HealingAdvisors.production(environment:)` (`.../Healing/HealingAdvisors.swift:13`) picks the advisor from the
  environment and the OS. It takes no config. `FleetEngine.Dependencies.live` (`.../FleetEngine/FleetEngine.swift:302`)
  calls it.
- `HealingAgent+Escalation.swift:87` returns false unless `policy.ai == .auto`.
- Config: `HealingConfig.AIMode` is `auto | off`. Parsing is in `ConfigLoader+Fleet.swift:151`, the DTO in
  `ConfigDTO.swift:167`, the schema in `ConfigSchema.swift:34`, and the commented example in `ConfigTemplate.swift:146`.
- The journal detail reads `"\(advisor.name) chose …"` (`HealingAgent+Escalation.swift:79`), so a cascade needs the model
  that answered to reach it.

## Recommended approach

**1. Config.** `ai` becomes `auto | off | ollama`. A new nested block:

```yaml
healing:
  ai: ollama
  ollama:
    host: http://127.0.0.1:11434   # default; https required for any other host
    model: my-custom-model         # the LLM, required with ai: ollama
    fast_model: clef-flash         # System 1: a decision model, asked first; omit for LLM only
```

- `HealingConfig`: add `.ollama` to `AIMode`, plus `OllamaConfig { host: URL; model: String; fastModel: String? }`.
- `PartialHealing` gets `ollama: PartialOllama?` (`host`, `model`, `fast_model`). Add it to `ConfigSchema` as a nested object.
- `parseHealing` (`ConfigLoader+Fleet.swift`): the `ai` error text now lists `auto, off or ollama`. With `ai: ollama`,
  `model` is required. `fast_model` must differ from `model`. `host` must parse as an http(s) URL, and a non-loopback
  host must be https. `ollama` keys without `ai: ollama` are an error, so a half-set block cannot silently do nothing.
  Every error names its key, as today.

**System 1 is Ollama's decision endpoint, not chat.** Ollama 0.35+ serves `POST /v1/systemone`. Its models
(`clef-flash`, `nimble`, `nimble-v3`, `tev1`) take a `state` plus named `questions` and return a probability for each
option in one forward pass, not generated text. That fits the advisor's job better than a JSON chat reply: a `choice`
question whose options are the candidate kinds plus `none`. `fast_model` must name one of these decision models.

Request and response shape (from `ollama.com/blog/ollama-now-supports-jev-style-decision-models`; verify against a live server):
- Request: `{"model", "state", "questions": {name: {"type": "choice", "instructions", "criteria": {option: description}}}}`.
- Response: `{"answers": {name: {"choice", "probabilities", "confidence"}}, "usage"}`.
- The response has no reasoning text. The cascade's journal explanation for a System 1 answer is therefore generated by
  kinhin: "System 1 (<model>) chose X with probability P". The LLM tier still returns its own explanation.
- Confidence rule (my choice): System 1 is "confident" when its choice is not `none` and its probability for that choice
  is at least 0.8. `confidence` in the response is documented as its own measure and is not used for this.

**Examples to run once Ollama is installed** (both are sent to `/v1/systemone`; the advisor builds the same shape from the
request):

`clef-flash` (Apache 2.0, 9B, 11 GB, needs Ollama 0.35.1+):

```bash
curl http://127.0.0.1:11434/v1/systemone -d '{
  "model": "clef-flash",
  "state": "warm VM vm-3 is missing from tart list. log: tart: no such VM vm-3",
  "questions": {
    "fix": {
      "type": "choice",
      "instructions": "Which fix addresses the cause?",
      "criteria": {
        "delete_vm_record": "Forget the VM record so the fleet respawns it",
        "none": "No listed fix addresses the problem"
      }
    }
  }
}'
```

`nimble` (the earlier release, same request shape; the blog's example uses this tag). Ollama's blog lists it as
Apache 2.0 in coverage, but check the library page before relying on that:

```bash
curl http://127.0.0.1:11434/v1/systemone -d '{
  "model": "nimble",
  "state": "warm VM vm-3 is missing from tart list. log: tart: no such VM vm-3",
  "questions": {
    "fix": {
      "type": "choice",
      "instructions": "Which fix addresses the cause?",
      "criteria": {
        "delete_vm_record": "Forget the VM record so the fleet respawns it",
        "none": "No listed fix addresses the problem"
      }
    }
  }
}'
```

Expected response shape (illustrative numbers): `{"answers": {"fix": {"choice": "delete_vm_record", "probabilities": {"delete_vm_record": 0.91, "none": 0.09}, "confidence": 0.8}}, "usage": {...}}`.

**Model notes that affect the plan:**
- `nimble-v3` (the newer release) is **CC BY-NC 4.0, noncommercial only**. It needs Ollama 0.40.4+, text input only, a
  32K-token limit on the whole request, and about 9 GB at its default tag. The `nimble` release is not the same license.
  Whether kinhin's use is commercial decides which one is usable; `clef-flash` (Apache 2.0) is the safe default.
- Context windows conflict across sources for `clef-flash` (256K in one listing, 64K in the README highlights). Plan
  around the smaller figure, which is enough for the 4,096-token prompt budget.
- Decision models are 9B and about 6–12 GB, so "small System 1" in the earlier draft means a 9B decision model here.
  That needs the memory check below.
- The Ollama Python and JS libraries do not expose `/v1/systemone` yet, so the advisor uses raw HTTP, as the chat tier does.

**2. Shared prompt code.** Move `instructions`, `none`, `prompt(for:budget:)` and the prompt-budget sizing out of
`FoundationModelsHealingAdvisor` into a new `HealingPrompt.swift` with no FoundationModels import. Foundation Models keeps
only its schema and session code. Its tests move to the new location.

**3. Ollama advisors.** New `Sources/KinhinKit/Fleet/Healing/OllamaHealingAdvisor.swift`. Two wire formats, one per tier:
- LLM tier: `OllamaHealingAdvisor` posts to `/api/chat` with a JSON-schema `format`.
- System 1 tier: `OllamaDecisionAdvisor` posts to `/v1/systemone` with one `choice` question (section above). Both have
  `host`, `model`, an injectable `URLSession`, and a `timeout` (both tiers: 60 s, because a local model may
  cold-start). `name` is `"ollama:<model>"`.
- A version check: `GET {host}/api/version` must report 0.40.4 or later for `nimble-v3`, and 0.35.1 or later for
  `clef-flash`. An older server is "not available" with a reason, not a crash.
- `isAvailable()`: `GET {host}/api/tags`, and check the model is listed (exact name, or `name:latest` when no tag is
  given). Any error means not available. The agent caches the answer for `advisorRecheck`.
- `advise()`: `POST {host}/api/chat` with `stream: false`, messages (instructions, then the prompt), and `format` set to a
  plain JSON schema: `remediation` (an enum of the candidate kinds plus `"none"`), `confident` (boolean), `explanation`
  (string), all required. `options`: `temperature: 0`, `num_predict: 200`, `num_ctx: 4096`. The prompt budget is the same
  as Foundation Models'. Decode `message.content` as JSON and map it to `HealingAdvice`, with `LogRedactor.redact` on the
  explanation. Run it under `HealingDeadline.run` with the timeout above. Available on macOS 15 too.

**4. Cascade.** New `CascadingHealingAdvisor: HealingAdvisor` in `HealingAdvisors.swift` (or its own file), holding an
optional System 1 advisor and an LLM advisor:
- `isAvailable()`: true when either tier is available.
- `advise()`: ask System 1 when it is available. Its answer is final when it is confident and picks a fix (not `none`).
  Otherwise ask the LLM when it is available. If the LLM gives no answer or fails, return System 1's answer as it is.
  A doubtful or "none" System 1 answer is still handled by the agent's existing rules (surfaced, never run).
- Each `HealingAdvice` gets a `model: String?` (default nil, set by the tier that answered). The journal and
  `kinhin heal` use it, so the detail reads `"ollama:clef-flash chose …"` or `"ollama:my-custom-model chose …"`.
- Without `fast_model`, the cascade is just the LLM advisor.

**5. Selection and wiring.**
- `HealingAdvisors.production(config:environment:)`: keep the debug stub override first. Then `.ollama` builds the
  cascade from the config, `.auto` gives Foundation Models on macOS 26+ (else `NoHealingAdvisor`), and `.off` gives
  `NoHealingAdvisor`.
- `FleetEngine.Dependencies.live` takes the healing config. `FleetEngine+Production.swift` passes the config's `healing`
  section. Update the callers and tests of `production(environment:)` and `live`.
- `HealingAgent+Escalation.swift:87`: `policy.ai == .auto` becomes `policy.ai != .off`. Journal detail uses
  `advice.model ?? advisor.name`.

**6. Surfaces and copy.**
- `kinhin heal` (`HealCommand.swift:101`): `"; ollama:<model> advises on the rest"`. When the advisor is configured but
  unavailable, say why in one line (a model is not pulled, or the host is unreachable). If that needs a reason on the
  snapshot and that is too big for this change, keep "rules only" and leave the reason for a follow-up.
- App: `HealingPresentation.swift` and `Localizable.xcstrings` describe the advisor as "the on-device model". Change the
  wording where the advisor may be Ollama, and keep the Apple Intelligence wording where it is that model.
- `ConfigTemplate.swift`: document `ai: ollama` and the `ollama:` block.

**7. Docs (the privacy change).**
- `docs/healing.md`: the config block; a new "Ollama advisor" section (`ollama pull` or `ollama create`, the two model
  keys, the host default, and exactly what is sent); the advisor and requirements paragraphs, which currently describe
  only Apple Intelligence.
- `docs/security.md` (around lines 71-72): Apple Intelligence still makes no network call. With `ai: ollama`, the
  redacted problem and log lines go to the configured host, which may be remote over https.
- `docs/plans/healing-agent.md` section 4 config line. A CHANGELOG entry under Unreleased.
- Run `scripts/docs-sync.sh --check` and `cd website && npx vitepress build` (CLAUDE.md).

**Out of scope:** a live e2e lane against Ollama. CLAUDE.md and the memory rule put e2e runs in CI only, so that is a
follow-up dispatched through `e2e.yml`. Pulling models for the user is also out of scope, as are changes to the rules or
the allowlist.

## Open items to confirm when approving

- The https-for-remote-hosts guard is mine, not in your answers. Say if you want plain http for remote hosts too.
- Apple Intelligence is not in the cascade. It could be the System 1 tier instead of a decision model, if you want
  that option later.
- The 60 s timeouts are constants, not config keys.
- Is kinhin used commercially? That decides whether `nimble-v3` (CC BY-NC) can be the default System 1 model. The
  examples use `clef-flash` and `nimble`; check the `nimble` license on its library page before choosing it.
- System 1 is a 9B decision model here, not a small chat model. Both System 1 candidates need about 6–12 GB of memory
  alongside the LLM. The memory budget needs a decision before a default is picked.
- The 0.8 probability threshold for "confident" is a guess. Measure it on real problems before it is trusted.
